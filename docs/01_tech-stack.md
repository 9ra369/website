# 技術スタック提案

対象: CG・VFXの知識/参考リンクを体系的にまとめる個人アーカイブサイト
規模: 個人Wikiレベル（数十〜数百記事、更新者は自分のみ）
方針: サーバー管理コストを抑えつつ、無料ホスティング→将来の有償プラットフォーム移行がスムーズにできる構成

## 全体方針: 静的サイト（SSG）一択

- 更新者が自分だけ、DB管理者・多人数編集が不要 → CMSやサーバーサイドDBは過剰投資
- 静的サイトは「無料ホスティングで始めて、後で有償/自前サーバーに引っ越す」が最も簡単（ファイルをコピーするだけで完結、DB移行が発生しない）
- 表示速度・SEO・保守性のバランスが良く、広告収益化とも相性が良い（広告以外のサーバー負荷がほぼゼロ）

## サイトジェネレーター（SSG）比較

| 項目 | **Astro（推奨）** | VitePress | Hugo | Eleventy |
|---|---|---|---|---|
| コンテンツ管理 | Content Collections（型安全なfrontmatterスキーマ、Zodでバリデーション） | 素朴なMarkdown＋frontmatter | Front Matter＋タクソノミー機能が強力 | 柔軟だが型安全性は自前実装 |
| デザインの自由度 | 高い（素のHTML/CSSベース、React/Vue部品も混在可） | 低め（ドキュメントサイト的レイアウトが前提） | 中（Goテンプレートに慣れが必要） | 高い |
| ビルド速度 | 速い | 非常に速い | 最速クラス | 速い |
| 学習コスト | 低〜中 | 低 | 中（独自テンプレート言語） | 低 |
| 検索・画像最適化・RSS等の公式連携 | 豊富（Pagefind, Astro Image, @astrojs/rss等） | 内蔵検索ありだが簡素 | 自前実装が多い | 自前実装が多い |
| 「リンクキュレーション型DB」との相性 | ◎（frontmatterスキーマでURL/カテゴリ/タグ/評価/メモを型定義できる） | △（ドキュメント階層向け） | ○（タクソノミー機能で近いことは可能） | ○ |

**結論: Astro を採用。** 理由は、キュレーション記事（外部リンク＋自分のコメント・評価）を構造化データとして型安全に管理でき、かつデザインを「ドキュメントサイト」の型にはめられず自由に作れるため。今回作成するミニマル×ホワイトの独自デザインとも相性が良い。

## 採用スタック詳細

| レイヤー | 採用技術 | 理由 |
|---|---|---|
| SSG フレームワーク | **Astro** | 上記の通り。将来React等のインタラクティブ部品も部分導入しやすい（Islands Architecture） |
| コンテンツ管理 | **Astro Content Collections（Markdown/MDX）** | 記事＝Gitで管理されるテキストファイル。CMS不要、バックアップ＝Git履歴 |
| スタイリング | **Tailwind CSS** | ユーティリティファーストでプロトタイプ→本実装の移行が速い。未使用CSSは自動でパージされ本番バンドルが小さい |
| 全文検索 | **Pagefind** | ビルド時に静的インデックスを生成、サーバー・API不要でクライアント完結の検索を実現。個人Wiki規模と完全に一致 |
| 画像最適化 | **astro:assets（組み込み）** | サムネイル画像の自動リサイズ・WebP変換・遅延読み込み |
| フォント | Noto Sans JP + Inter | 日本語と英数字の両方で可読性の高い組み合わせ |
| バージョン管理 | **GitHub（プライベートリポジトリ）** | コンテンツのバックアップ＝コミット履歴。後にOSS化や別端末での編集も容易 |
| アクセス解析 | **Cloudflare Web Analytics** | Cookie不要・無料・ページ表示速度に影響しないbeacon型。GA4は今回はオーバースペック＆Cookie同意バナー対応が必要になるため見送り推奨 |
| 広告 | **Google AdSense** | 静的サイトでも`<script>`タグ設置のみで導入可能。審査には一定の記事数・独自性のある文章（リンク羅列だけでなく自分の解説/メモを添える）が必要な点に注意 |
| RSS | **@astrojs/rss** | 更新をXよりも資産として追いやすい形で配信。将来的にニュースレター化も可能 |
| コメント（任意・将来） | **giscus** | GitHub Discussionsベース。無料、自前DB不要、スパム管理もGitHubに委任できる |

## 移行のしやすさ（無料→有償プラットフォーム）

Astro/静的サイトの最大の利点は「ビルド成果物（HTML/CSS/JS一式）をどこに置いても同じように動く」こと。
そのため、以下のような段階的な移行が可能：

1. **Phase 1**: Cloudflare Pages（無料）でホスティング
2. **Phase 2**: 収益化が進んだら、同じビルド成果物をVPSや有償プランへそのまま移行（DB移行や書き直しが発生しない）

詳細な比較は [`02_platforms.md`](./02_platforms.md) を参照。

## 採用しないもの（検討したが見送り）

| 技術 | 見送り理由 |
|---|---|
| WordPress | DB・プラグイン管理の運用コストが個人Wiki規模には過大。ページ表示速度もSSGに劣る |
| Next.js | React SPA前提の機能（複雑なルーティング・SSR）は今回不要。Astroの方が静的コンテンツ主体のサイトに軽量で適合 |
| Notion / Notion公開機能 | 手軽だが検索・SEO・デザイン自由度・独自ドメイン運用に制約があり「資産化」の目的に対して弱い |
| Docusaurus / VitePress | ドキュメントサイト向けレイアウトが強制されやすく、「キュレーションDB＋ギャラリー的」なデザインをゼロから作るには自由度が低い |
