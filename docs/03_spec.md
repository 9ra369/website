# サイト仕様書

サイト名: **Merge VFX&CG**（ドメイン候補: `merge-vfx-cg.com`）

## 1. 目的・背景

- これまでX（旧Twitter）等で発信・収集してきたCG/VFX関連の情報を、体系的に整理し直して「資産」として残す
- AIの普及によってキュレーション・知識そのものの価値が相対的に下がる前に、自分の知見・視点をアーカイブ化する
- Xの時系列フローに流れて埋もれてしまう情報を、カテゴリ・タグで検索/参照可能な「ストック」型の情報源に変換する
- 将来的に広告収益でサーバー代（実質は独自ドメイン代＋任意のプラン費用）を賄う

## 2. 想定ユーザー

| ユーザー像 | ニーズ |
|---|---|
| 自分自身（管理者） | 過去に集めた情報を素早く再発見・追記できること |
| CG/VFXを学ぶ学生・独学者 | ツール別・工程別に整理された良質な参考リンクを見つけたい |
| 現役アーティスト・TD | 特定ソフト（Houdini/Nuke等）のニッチな情報を探したい |
| 検索エンジン経由の訪問者 | 個別記事（特定チュートリアルの評価・補足情報）にピンポイントで到達したい |

## 3. 情報アーキテクチャ（カテゴリ設計）

カテゴリは [`data/categories.json`](../data/categories.json) を正とするデータ管理に変更（2026-08-08〜）。ハードコードせず、この JSON を読み込んで各ページ（カテゴリ一覧・フィルタ・カード等）を生成する想定。

| slug | label |
|---|---|
| `environment` | Environment |
| `pipeline` | Pipeline/Plugin/Tool |
| `article` | Article |
| `showreel` | Showreel/Demoreel |

> 以前は制作工程に沿った11カテゴリ（モデリング/サーフェシング/ライティング…）を暫定採用していたが、運用しやすさを優先して上記4カテゴリに整理し直した（Compositingは統合され廃止）。ソフト名（Houdini等）や技法名は`category`ではなく`tags`側で表現する（[04_content-guide.md](./04_content-guide.md)参照）。
>
> カテゴリは引き続き`categories.json`に追加・分割していく前提の可変リストであり、確定版ではない。

## 4. コンテンツ・データモデル

1エントリー = 1つの外部リンク（または自作コンテンツ）+ 自分の解説・評価。Markdownファイル1本に対応。

```yaml
---
title: "Houdini Vellum入門: 布シミュレーションの基礎"
url: "https://example.com/houdini-vellum-tutorial"   # 外部参照先（自作記事の場合は省略可）
category: "simulation-fx"        # 大カテゴリのslug
tags: ["Houdini", "Vellum", "クロスシム", "チュートリアル"]
type: "tutorial"                 # tutorial | article | tool | reel | interview | resource | note
level: "beginner"                # beginner | intermediate | advanced
software: ["Houdini"]
thumbnail: "/images/entries/houdini-vellum.jpg"
summary: "Houdini Vellumソルバーを使った布シミュレーションの基本ワークフローを解説した入門記事。"
memo: |
  パラメータの初期値の目安として参考になった。
  自分のプロジェクトでは重力を弱めに調整して破綻を回避した。
rating: 4              # 自己評価 1-5（星の代わりに数値管理、表示は★）
sourceLang: "en"       # 参照先の言語
---
（任意の本文: memoより長い考察や補足を書く場合はここに）
```

この構造により、単なるブックマーク集ではなく「自分の視点が付加された一次情報」となり、AdSense審査・SEO・将来の資産価値の面で有利になる。

## 5. ページ構成

| パス | ページ | 内容 |
|---|---|---|
| `/` | トップ | ヒーロー、コンセプト説明、注目カテゴリ、新着エントリー |
| `/archive` | アーカイブ一覧 | 全エントリーをカテゴリ・タグ・ソフト・レベルでフィルタ、検索窓 |
| `/category/[slug]` | カテゴリ別一覧 | そのカテゴリに属するエントリー一覧 |
| `/tags/[tag]` | タグ別一覧 | 横断タグでの一覧 |
| `/entry/[slug]` | エントリー詳細 | 個別ページ（詳細解説・関連エントリー・外部リンクへの導線） |
| `/about` | このサイトについて | 目的、運営者情報、お問い合わせ（AdSense審査対策としても必須） |
| `/privacy` | プライバシーポリシー | Cookie/広告に関する開示（AdSense必須） |
| `/rss.xml` | RSS | 更新配信 |

## 6. 機能要件

- カテゴリ／タグ／使用ソフト／レベルでの絞り込み
- キーワード全文検索（Pagefind、クライアントサイド完結）
- 並び替え（新着順・アルファベット順の2種類のみ）
- パンくずリスト
- 関連エントリー表示（同カテゴリ・同タグ優先）
- レスポンシブ対応（PC・タブレット・スマホ）
- OGP／Twitter Card対応（SNSシェア時のサムネイル表示）
- RSS配信
- 広告枠（記事一覧・詳細ページに配置。AdSense審査通過後に段階導入）
- サイトマップ自動生成（SEO）

**対象外（実装しない）**: いいね／リアクション機能、コメント以外のユーザーアカウント機能全般。個人アーカイブとしてのシンプルさを優先し、ソーシャル機能は持たない方針。

## 7. 非機能要件

- Lighthouseパフォーマンススコア 90以上を目標（静的サイトのため達成容易）
- アクセシビリティ: コントラスト比AA準拠、画像alt必須、キーボード操作対応
- SEO: 構造化データ（Article/BreadcrumbList）、meta description自動生成
- 保守性: Markdownファイルの追加・編集のみで更新完結。ビルド・デプロイはGit push契機で自動化（CI/CD）

## 8. デザイン方針

- **トーン**: ダーク基調＋アクセントは最小限（5%ルール）。VFXツール（Nuke/Houdini等）のUIを思わせる落ち着いた質感を、カード型グリッドで構成
- **配色**: `black_white_blue5_final` パレットを採用
  - 背景: `#0F1418`（メイン）/ `#1A2128`（カード面）
  - ボーダー: `#2B333B`（0.5px）
  - テキスト: 見出し `#FFFFFF`、本文 `#B9C2C9`、補助 `#7C8791`
  - アクセント: `#4B9FD0`（使用比率は全体の約5%に抑える。CTA等のベタ塗り面のみ濃い紺 `#06222F` を文字色として使用）
- **サイトアイコン / ロゴ**: ノードグラフ風アイコン（紫 `#8B7ED8` × グリーン `#1D9E75`）を採用。favicon・ヘッダーロゴ双方で使用し、サイト配色（黒/白/青）とは独立したブランドマークとして扱う
- **タイポグラフィ**: 見出し・本文ともにNoto Sans JP（和文）+ Inter（英数字）
- **レイアウト**: カード型グリッドによるエントリー一覧、サムネイルは16:9で統一
- **余白**: 情報密度を上げすぎず、余白を広めに取り「アーカイブ」らしい落ち着きを出す

詳細はHTMLプロトタイプ（[`prototype/`](../prototype/)）を参照。運営者プロフィールリンクは [`data/personal.json`](../data/personal.json) で一元管理し、フッターの「Connect」欄に反映する。
